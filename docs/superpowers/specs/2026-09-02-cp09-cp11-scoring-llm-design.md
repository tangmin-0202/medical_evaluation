# CP09/CP11 阶段性评分与 LLM 点评设计

## 目标与范围

当前纵向链路只自动评估 CP09 和 CP11。CP01 暂时搁置，与 CP02–CP08、CP10 一样保留在 11 项 rubric 和报告结构中，但不调用特征提取器或 Judge，也不参与阶段性分数。

本阶段交付一条可运行链路：真实视觉特征 → 确定性 Judge → 阶段性评分 → 本地 Qwen 中文点评 → 11 项报告。它是功能验证，不代表完整考核成绩或泛化准确率。

## 状态与评分

- CP09、CP11 使用现有确定性 Judge 输出 `correct`、`incorrect`、`incomplete` 或 `needs_review`。
- 其余 9 项生成 `needs_review`，使用独立原因码 `automatic_evaluation_not_implemented`，且标记为未纳入本次评分。
- 报告保留 11 个考核点，顺序和 rubric 不变。
- 新增阶段性评分字段：`evaluated_count`、`total_count`、`provisional_score`。
- CP09、CP11 中实际取得自动证据并产生确定性结论的项目参与计算；Judge 返回 `needs_review` 时产生阶段性上下界，因缺少模型输入而未运行的项目完全排除。
- 两项均有确定性结论时，各占阶段性 50 分。例如一项正确、一项错误时，阶段性得分为 50 分。
- 正式 11 项 `final_score` 始终为空。页面按视频显示实际数量，例如成功视频为“已评估 2/11 项”，当前两个失败视频通常为“已评估 1/11 项”，并始终标注“阶段性结果，非最终成绩”。不能把阶段性分数显示成正式 `/100` 总分。

## 真实管线边界

`AnalysisPipeline` 显式接收或保存启用的考核点集合，本阶段固定为 `cp_09`、`cp_11`。循环仍生成 11 项结果，但只有启用项调用对齐、提取器和 Judge。这样不会因其他 Judge 函数已经存在而错误运行 CP01 或尚未实现的考核点。

CP09 和 CP11 继续使用各视频人工确认的时间段与现有提示。CP11 可以复用 CP09 支架跟踪数据，但 CP09、CP11 的判定和得分彼此独立。

CP09 只有在当前视频同时具备有效 `rubber_dam_frame` 提示和唯一 `oral_region` 框时才运行。缺少这些输入时生成 `needs_review` 结果，原因码为 `automatic_evaluation_input_missing`，并标记为未纳入阶段性评分。不得使用人工阶段标签冒充自动结果。当前 `success` 可运行 CP09；另外两个视频暂时跳过 CP09，待未来 SAM3 无提示/文本提示检测接入后补齐。

CP11 的绿色橡皮布全阶段扫描可独立运行，因此三个视频均进入 CP11 自动评估。只有 CP11 的成功路径需要复用 CP09 支架参考；若到达该路径但参考缺失，则返回证据不足而不是猜测结论。

## LLM 点评

LLM 输入仅包含：rubric 名称与标准、确定性状态、原因码、数值特征以及最多三张派生证据图。原始视频不发送给 LLM。

每个已自动评估的考核点生成结构化点评：证据是否支持结论、中文解释、中文改进建议、引用的证据索引和来源。点评作为独立字段保存，不覆盖 Judge 的状态、原因码、规则或得分。

报告总评由 CP09、CP11 的确定性状态和两项结构化点评组合生成，并明确说明只评估了 2/11 项。若 Qwen 服务不可用、超时或返回非法 JSON，使用确定性中文模板回退，报告和评分仍能正常生成。

LLM 响应 schema 禁止额外字段，并保持 `score_override` 只能为 `null`。任何试图输出分数或改变确定性状态的响应都视为无效并回退。

## 应用与配置

真实模式启动时由应用工厂构造 CP09/CP11 真实提取器、确定性管线和 Qwen 客户端。Qwen 使用现有 `MED_EVAL_VLM_BASE_URL` 与 `MED_EVAL_VLM_MODEL` 配置。

本阶段不把默认模式静默改成真实模式。服务器必须显式设置 `MED_EVAL_PIPELINE_MODE=real`，且缺少 SAM2 配置、权重或真实管线依赖时应在启动阶段给出清楚错误，不能回退成假结果。

## 页面展示

报告页顶部显示：

- “阶段性得分”或阶段性区间；
- 实际已评估数量，例如“已评估 2/11 项”或“已评估 1/11 项”；
- “非最终成绩”。

CP09、CP11 卡片分别展示确定性原因、规则、特征、证据和“AI 点评”。其他项目显示“尚未接入自动评估”，不显示为操作失败，也不计作 0 分。

## 错误处理与审计

- SAM2 OOM 仍只降级重试一次，并记录在运行审计中。
- 第二次 OOM 或真实提取失败使任务失败，不伪造评分。
- LLM 失败只影响点评，不影响确定性报告与阶段性评分。
- 审计记录真实管线版本、视觉模型版本、点评模型名以及回退信息。

## 验证

采用测试驱动方式覆盖：

1. 真实管线只考虑 CP09、CP11，绝不调用 CP01 或其他未完成提取器；
2. 缺少必需 CP09 提示时不调用 CP09 提取器，并将其排除在阶段性评分外；
3. 其余 9 项为未实现状态且不参与阶段性评分；
4. 两项一对一错得到阶段性 50 分，只有一项参与且正确时得到阶段性 100 分；
5. 已运行项目存在 `needs_review` 时返回阶段性区间而非确定分；
6. LLM 点评无法覆盖状态和分数；
7. Qwen 不可用时模板回退且报告仍可保存；
8. 报告页显示实际评估数量、阶段性和非最终成绩。
