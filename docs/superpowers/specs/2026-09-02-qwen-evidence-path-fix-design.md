# Qwen 证据图路径修复设计

## 问题

真实任务报告将证据图保存为可移植的任务内相对路径，例如
`cp_09/overlays/00008802.jpg`。点评客户端直接从进程工作目录读取该路径，
因此找不到实际位于 `data/jobs/<job_id>/` 下的文件，并在两次失败后回退到
`template_fallback`。

## 设计

保留报告中的相对路径不变。`AnalysisPipeline` 在构造
`VlmReviewRequest` 时，以当前任务目录 `output_root / job.id` 为根目录解析每个
证据路径，再把解析后的文件路径交给 Qwen 客户端。

该修复只改变点评请求读取证据图的位置：不改变提取器输出、报告路径、网页资源
地址、Judge 状态、原因、分数或阶段性计分规则。

## 系统提示词

系统提示词首句明确限定为“你是牙科操作考核的证据点评助手，现在需要对橡皮障
隔离技术相关操作进行点评。”其余关于证据来源、图片索引、JSON 格式、禁止改分和
禁止覆盖确定性结论的约束保持不变。

## 验证

新增管线回归测试，在临时任务目录创建证据图，并验证点评提供者收到的是存在的
任务目录内路径。测试应先在旧实现下因收到错误相对路径而失败，再由最小实现使其
通过。另用单元测试锁定完整系统提示词。随后运行点评与管线相关测试、完整测试和
Ruff。
