# 橡皮障隔离术视频智能考核 Demo 设计

日期：2026-08-21

## 1. 背景与现有资料

项目当前包含：

- `橡皮障隔离术操作解析.xlsx`：1 个工作表，列为“视频时间段”“操作考核点”“考评点”，共 11 个考核点。
- `橡皮障完整.mp4`：成功样例，约 4 分 59 秒，1920×1080，约 50 fps。
- `橡皮障夹子飞了.mp4`：失败样例，约 3 分 14 秒，1920×1080，约 50 fps。
- `橡皮障失败.mp4`：失败样例，约 5 分 21 秒，1920×1080，约 50 fps。
- Ubuntu GPU 服务器：8 张 NVIDIA RTX A5000，每张约 24 GB 显存，可使用空闲 GPU 运行本地模型。

三个视频的拍摄机位和操作步骤顺序基本固定，但每个步骤的实际起止时间不同，失败视频可能漏做或提前结束。

## 2. 目标

构建一个单用户网页 Demo，支持选择三个预置视频或上传同机位、同操作顺序的 MP4 视频，并输出：

1. 每个考核点的实际时间段。
2. `correct`、`incorrect`、`incomplete`、`needs_review` 四种状态之一。
3. 单项得分、置信度、错误原因和改进建议。
4. 可追溯证据：关键帧、SAM 掩码叠加图、特征值和命中规则。
5. 0–100 分总分或待复核情况下的分数区间。
6. 本地开源视觉语言模型生成的逐项评价和中文总评。

该 Demo 用于验证技术链路和展示效果，不声明对新操作者或新机位具有统计意义上的泛化准确率。

## 3. 非目标

第一版不实现：

- 用户登录、权限、多租户或多任务并发调度；
- 云存储、移动端、实时摄像头或实时评分；
- 正式考试防作弊或临床决策；
- 直接使用 3 个视频训练端到端动作分类器；
- 对不同机位、任意步骤顺序或明显不同器械套装做可靠泛化。

## 4. 核心设计决策

采用“视觉证据融合”路线：

```text
视频
  → 动态步骤定位
  → SAM 分割与跨帧跟踪
  → 时序特征矩阵
  → 步骤专属 Judge
  → 确定性评分
  → Qwen3-VL 受约束复核与中文点评
  → 网页报告
```

关键约束：

- SAM 只提供对象掩码、位置和轨迹，不直接输出操作对错。
- 分数由规则、状态机和参考相似度计算；LLM 不得直接改写分数。
- 看不清、未检出或模块冲突时输出 `needs_review`，不得静默猜测。
- 三个现有视频使用人工确认的步骤时间和逐项标签作为真值。

## 5. 模型选择与许可证

### 5.1 分割模型

默认评估 SAM3.1。它支持文本、点、框和掩码提示，并能在视频中检测、分割和跟踪对象。代码通过适配器隔离，保留 SAM2.1 回退路径：

- SAM3.1：优先用于文本概念提示和多对象视频跟踪；使用前接受并核对 Meta SAM License。
- SAM2.1：当 SAM3.1 在 RTX A5000 上显存、依赖或授权不合适时回退；官方代码和检查点采用 Apache-2.0。

官方来源：

- https://github.com/facebookresearch/sam3
- https://github.com/facebookresearch/sam3/blob/main/RELEASE_SAM3p1.md
- https://github.com/facebookresearch/sam2

### 5.2 本地视觉语言模型

采用 `Qwen3-VL-4B-Instruct`，通过 vLLM 或 Transformers 在服务器本地运行。选择 4B 是为了先保证单张 A5000 24 GB 上的稳定部署；效果不足时可切换 8B 或量化模型，接口保持不变。Qwen3-VL 仓库使用 Apache-2.0：

- https://github.com/QwenLM/Qwen3-VL

Qwen3-VL 的输入仅为考核标准、少量关键帧、SAM 叠加图和结构化特征，不发送完整视频到外部服务。

## 6. 输入数据

### 6.1 原始输入

- MP4 视频；
- 原始 Excel 考核表，保持只读；
- SAM 与 Qwen 模型权重，存放在 Git 仓库之外。

### 6.2 考核规则 `rubric.yaml`

由 Excel 转换并人工校验，包含：

```yaml
checkpoints:
  - id: cp_01
    name: 在橡皮布上确定隔离牙位
    criterion: 选择正确的打孔点位并做标记
    weight: 0.090909
    judge_type: geometry
    required_objects: [rubber_dam, mark]
    reference_video: success
    reference_time: [0.0, 14.0]
    thresholds:
      mark_position_distance: calibrated
```

`calibrated` 表示阈值不硬编码在程序里；它由成功样例、两个失败样例和人工真值校准后写回配置，并保留版本。

### 6.3 步骤与真值 `segments.json`

每个现有视频必须人工标注实际时间，不套用成功视频绝对时间：

```json
{
  "video_id": "failure_clamp_flew",
  "steps": [
    {
      "checkpoint_id": "cp_01",
      "start_sec": 0.0,
      "end_sec": 16.8,
      "label": "correct",
      "reason": "打孔点位正确"
    }
  ]
}
```

允许标签为 `correct`、`incorrect`、`incomplete`、`needs_review`。所有人工修改记录操作者、时间和修改前后值。

### 6.4 SAM 提示 `prompts.json`

在成功视频及必要的失败关键帧上，一次性标记对象：

```json
{
  "video_id": "success",
  "frame_time_sec": 182.4,
  "object_id": "rubber_dam_frame",
  "prompt_type": "box",
  "coordinates_normalized": [0.12, 0.08, 0.91, 0.94]
}
```

提示类型支持点、框和已确认掩码。坐标归一化到 `[0, 1]`，避免依赖固定分辨率。

## 7. 动态步骤定位

Excel 时间仅是成功视频参考。其他视频采用固定顺序、可伸缩的单调序列对齐：

1. 以 1–2 fps 稀疏抽帧，得到视频全局扫描序列。
2. 提取短片段视觉嵌入、器械出现状态和场景变化特征。
3. 从成功视频的 11 个已标注片段生成步骤原型。
4. 使用 DTW 或 Viterbi 做单调对齐，只允许步骤按 1→11 前进，同时允许持续时间伸缩、跳过步骤和提前结束。
5. 使用事件锚点细化边界，例如打孔器接触、障夹出现、进入口腔、牙线出现和支架展开。
6. 输出每段候选起止时间与置信度。

三个预置视频同时保留人工真值和自动结果，用于计算时间段交并比及边界误差。新上传视频若边界置信度不足，网页将该段标黄并允许拖动边界后重新分析。

漏做步骤不能用相邻片段强行填充；证据持续缺失时标记 `incomplete`。视频提前结束后尚未出现的步骤统一标记 `incomplete`。

## 8. SAM 输出与时序特征矩阵

每个步骤产生一个 `T × F` 特征矩阵。`T` 是采样时间点，`F` 包括：

- 对象是否存在及检测置信度；
- 掩码面积、质心和边界框；
- 对象间距离、交并比和接触近似；
- 遮挡顺序与可见比例；
- 轨迹速度、方向和状态变化；
- 相对成功样例的外观/片段嵌入相似度；
- 指定区域的绿色或深色像素比例；
- 帧级质量：模糊、遮挡和越界。

第一版不把该矩阵直接输入 MLP、LSTM 或 XGBoost。三个视频最多产生约 33 个步骤样本，且同视频帧高度相关，学习型分类器会记住视频而非学会操作。矩阵先交给透明规则、状态机和相似度 Judge。积累数十名操作者、每项有足够独立正负样本后，再评估学习型时序分类器。

## 9. 十一个考核点的 Judge

| ID | 考核点 | 主要对象/证据 | 判定方式 |
|---|---|---|---|
| 01 | 标记 36 牙打孔点 | 橡皮布、标记点、归一化位置 | 与成功参考点的几何距离 |
| 02 | 选择孔盘第二孔并检查残留 | 孔盘、孔洞、探针、绿色残留 | 第二孔位置规则 + 清理动作 + VLM 复核 |
| 03 | 打孔并上下提拉 | 打孔器尖端、橡皮布、孔洞 | 接触/闭合/反向提拉状态机 |
| 04 | 选择下颌磨牙障夹 | 障夹局部裁剪、轮廓和外观 | 参考相似度 + VLM 类别复核 |
| 05 | 障夹套入橡皮布孔洞 | 橡皮布、翼、喙、臂、弓 | 上下遮挡关系 + 绿色区域 + VLM |
| 06 | 夹钳撑开并锁定 | 夹钳、障夹开口、弹簧 | 开口距离与弹簧位移状态机 |
| 07 | 安放在目标牙颈部 | 目标牙、邻牙、障夹喙/弓 | 牙位、可见接触点和远中方向；遮挡时复核 |
| 08 | 橡皮布就位 | 器械、翼、牙、布、翼孔 | 工具类别、暴露/包裹、颜色与遮挡规则 |
| 09 | 支架居中 | 支架、橡皮布有效区 | 中心偏差几何规则 |
| 10 | 牙线通过近远中接触区 | 目标牙、邻牙、牙线/手轨迹 | 细线检测、双侧轨迹 + VLM |
| 11 | 调整至完全就位 | 橡皮布、支架、鼻口区域 | 鼻口重叠率和支架覆盖率 |

第 7 项“四点接触”等不可见细节不能仅凭单视角推断。可见接触不足时输出 `needs_review`，并说明缺少的视角或证据。

## 10. 判定融合与评分

每个 Judge 输出：

- `status`；
- `confidence`；
- `feature_values`；
- `matched_rules`；
- `evidence_frames`；
- `reason_code`。

规则和 VLM 的职责如下：

- 几何、轨迹和颜色条件由确定性 Judge 决定。
- 需要器械类别或复杂遮挡语义时，VLM 输出受 JSON Schema 约束的辅助结论。
- VLM 与确定性证据冲突或置信度低时，最终状态为 `needs_review`。
- VLM 生成点评时只能引用已提供的结论和证据，不得新增未观察到的事实或改写得分。

11 项等权，总分 100。每项满分为 `100 / 11`，显示为 9.09，但内部保留高精度：

- `correct`：该项满分；
- `incorrect`：0 分；
- `incomplete`：0 分；
- `needs_review`：分数为 `null`。

存在待复核项时，页面显示最低分–最高分区间，最终总分为 `null`。人工确认后才生成最终 0–100 分，避免把“无法判断”伪装成错误或正确。

## 11. 输出数据

步骤结果示例：

```json
{
  "checkpoint_id": "cp_07",
  "time_range": [104.2, 126.8],
  "status": "incorrect",
  "score": 0.0,
  "confidence": 0.84,
  "evidence": [
    {"time": 116.4, "overlay": "evidence/cp_07_116.4.png", "rule": "bow_not_distal"}
  ],
  "features": {"contact_count_visible": 2, "bow_distal_probability": 0.21},
  "reason": "障夹弓部方向不符合参考位置",
  "suggestion": "重新确认远中方向后再安放障夹"
}
```

总报告还包含视频元数据、模型版本、规则配置版本、运行参数、运行时间、峰值显存、人工复核记录、最终总评和主要改进项。

## 12. 网页设计

采用 FastAPI 后端和轻量前端。第一版单用户、单任务队列，无登录。

页面流程：

1. 选择三个预置视频之一或上传 MP4。
2. 显示自动定位的 11 段时间轴、置信度和缺失步骤；允许拖动低置信度边界。
3. 启动分析并显示当前步骤、进度和失败信息。
4. 展示总分/分数区间及 11 项红黄绿状态。
5. 展开单项查看原视频时间、关键帧、SAM 掩码、特征、命中规则、原因和建议。

管理员标注页支持：

- 拖动并保存 11 个步骤起止时间；
- 选择逐项真值标签并填写错误原因；
- 在关键帧上点选或框选对象，由 SAM 生成并人工确认参考掩码；
- 查看和撤销人工修改记录。

## 13. 代码模块

- `web`：上传、时间轴、报告和标注页面；
- `video_pipeline`：视频校验、抽帧、缓存和关键帧；
- `step_localizer`：固定顺序动态对齐和置信度；
- `segmentation`：SAM2.1/SAM3.1 统一适配器、提示管理和跟踪；
- `features`：位置、接触、遮挡、颜色、轨迹和相似度提取器；
- `judges`：11 个独立 Judge；
- `vlm`：Qwen3-VL/vLLM 适配器、JSON Schema 校验和点评；
- `reporting`：评分聚合、证据文件和审计信息；
- `storage`：本地任务、标注、配置和运行结果。

模块只通过稳定数据对象通信。Judge 不直接访问网页、视频解码器或 LLM 服务，便于单元测试和后续替换。

## 14. GPU 与运行策略

- SAM 默认使用一张空闲 A5000；Qwen3-VL 使用另一张或复用已有 vLLM 服务。
- GPU 编号、模型路径、抽帧率和分辨率均为配置项，不硬编码。
- 单任务排队，模型进程只加载一次。
- 先低频扫描定位步骤，再仅对所需片段做密集分析，不逐帧处理原始 50 fps。
- 抽帧、掩码、特征和点评均按视频哈希、模型版本和配置版本缓存。

## 15. 异常与降级

- 视频损坏或格式不支持：拒绝任务并给出可操作错误信息。
- 步骤定位置信度低：暂停该步骤评分，提示用户调整时间段。
- 关键对象未检出或严重遮挡：输出 `needs_review`。
- SAM 运行失败：保留日志并允许单步骤重跑，不使用 VLM 猜掩码。
- Qwen 返回无效 JSON：按同一输入重试一次；再次失败后使用模板化点评，确定性分数不变。
- CUDA OOM：按配置降低抽帧率或分析分辨率后重试一次，并在报告中记录降级；仍失败则任务失败。
- 人工修正：保留原自动结果、修正值、操作者和时间，不覆盖审计记录。

## 16. 测试与验收

### 16.1 单元测试

- 时间和帧编号转换；
- DTW/Viterbi 单调顺序、跳步和提前结束；
- 掩码几何、接触、覆盖、颜色和轨迹特征；
- 11 个 Judge 的边界条件；
- 等权评分和待复核分数区间；
- Qwen JSON Schema、重试和模板降级。

### 16.2 集成测试

- 使用短视频夹段验证视频→SAM→特征→Judge→报告完整链路；
- 使用假 SAM/VLM 适配器验证无 GPU 的 Web 测试；
- 对同一视频、模型和配置重复运行，确定性分数一致；
- Qwen 服务不可用时，规则分数不变。

### 16.3 Demo 验收标准

- 三个预置视频均能从网页启动并生成完整 11 项报告；
- 每个 `correct` 或 `incorrect` 至少有一张关键帧、一个命中规则和相关特征值；
- 自动时间段可检查和修改，漏做及提前结束不会被错误填充；
- 输出逐项对照人工真值，报告混淆项和失败案例；
- 记录每个约 5 分钟视频的实际耗时和峰值显存，不承诺实时；
- 原始 Excel 与视频不被修改，模型权重、上传视频和派生证据不提交到 Git。

## 17. 实施顺序

1. 数据底座：Excel 转规则配置，完成三个视频步骤/真值标注和对象提示。
2. 纵向样例：先实现较容易验证的第 9、11 项，跑通视频→SAM→评分→网页。
3. 扩展 Judge：按难度实现其余九项并逐项验证证据。
4. 本地点评：接入 Qwen3-VL，限制为结构化复核和语言生成。
5. 回归演示：三个视频全流程回归、失败案例说明和服务器运行文档。

## 18. 隐私与数据管理

- 视频、关键帧和结果只保存在本地服务器，不调用外部 API。
- 上传和派生目录默认排除在 Git 之外。
- 报告不将 Demo 结果描述为临床诊断或正式考试结论。
- 数据保留周期由部署配置控制；第一版提供按任务删除派生结果的管理员操作，但不自动删除原始项目资料。
